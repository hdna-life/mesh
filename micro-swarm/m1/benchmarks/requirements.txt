Build a real inventory and reservation REST API with Python Flask and SQLite. Only Flask and the Python standard library are installed. app.py must run via python app.py, bind to 127.0.0.1 at PORT env var, enable concurrent request handling, and store SQLite at DATABASE_PATH env var. Initialize schema on startup without erasing data. No external network or subprocesses. The requested output file is selected by the engine; do not emit additional files. Use SQLite tables products(id,sku,name,stock) and reservations(id,product_id,quantity,request_key,status); reservations.product_id must reference products.id with a foreign key.
Product JSON: {id:positive integer,sku:string,name:string,stock:integer}. Reservation JSON: {id:positive integer,product_id:integer,quantity:integer,request_key:string,status:"active"|"cancelled"}. Return exactly these keys.
POST /products requires exactly {sku,name,stock}. SKU is ASCII [A-Z0-9-]{1,16}, unique case-sensitively; duplicate SKU returns 409. Name is a string stripped of surrounding whitespace, length 1..80. Stock must be an integer (not bool) 0..1000. Invalid input ->400 JSON object. Valid ->201 product.
GET /products ->200 JSON array ordered by id ascending. GET /products/<id> ->200 product or 404 JSON error.
POST /reservations requires exactly {product_id,quantity,request_key}. product_id is positive integer, quantity integer 1..100; bool is invalid. request_key is ASCII [A-Za-z0-9-]{1,64}. Unknown/missing fields, malformed JSON and non-object JSON ->400. Missing product ->404. Insufficient stock ->409. On success, decrement product stock and create reservation in ONE atomic transaction, returning 201 reservation. Stock must NEVER become negative, including concurrent requests. Failed requests must leave both tables unchanged.
Idempotency: Reusing request_key with identical product_id and quantity returns the original reservation with 200 (even if it is cancelled); never decrement stock again. Same key with a different product or quantity ->409 with no changes.
GET /reservations ->200 JSON array ordered by id ascending. 
POST /reservations/<id>/cancel accepts exactly {} JSON. Missing reservation ->404. Active reservation becomes cancelled, restoring quantity to its product in ONE transaction. Return 200 cancelled reservation. Repeated cancellation returns the same object with 200 and MUST NOT restore stock twice.
All rejected inputs use JSON object error bodies. No authentication. Products, reservations, stock deductions, idempotency and cancellations must survive process restart. SQLite PRAGMA integrity_check must be ok.
